## 2. 実装上の重要な指摘

### R1 / 高: `overruled` と証明探索の失敗が混同される

該当: `src/agent/nodes.py:450`（`proponent_move`）、`:503`（`_counter_failed`）、`:657`（`pop_and_propagate`）。

原論文は、justified を最小不動点で定め、overruled を justified な論証から攻撃される場合とする。対話木では P に strict defeat を要求し、P の論証に対する O の全 defeater を考慮する。一度の生成失敗は、その条件の検査になっていない。参照: [Prakken & Sartor (1997), Def. 2.15–2.16, 3.4, 4.5–4.8](https://webspace.science.uu.nl/~prakk101/pubs/DefArgJANCL97.pdf)（PDF通し12–13、16、24頁を画像で確認）。

**再現した反例:** ほかの論証がない `A ↔ B` で、Aを守る P が新しい C を生成しない場合。実装は `overruled` を返す。しかしこの閉じたグラフの最小不動点は空で、A/B はともに defensible。既存 A が B を攻撃しているか、B が justified なのかを、失敗経路は調べない。

「O の1手に対して採用する P の応答を1つにする」という生成戦略と、「最初の候補が無効なら代替候補も存在せず A は overruled」という推論は別物である。後者を原論文によって正当化してはいけない。

また、相互 defeat のある2論証が常に defensible になるわけでもない。例えば `B ↔ C, D → B` で D が無攻撃なら、D により C が復活しうる。現在の `contested_by` は局所探索の未解決フラグとしては理解できるが、一般の固定点分類器ではない。予算切れも「未判定」であって、意味論上の defensible の証明ではない。

**対処案:** まず研究上の状態を `search_failed / unresolved_mutual / budget_exhausted / survived_observed_attacks` 等の操作的状態として明示する。形式的な3値分類を主張するなら、攻撃関係を固定した小さなグラフで独立の意味論オラクルと照合し、別途その分類を実装する。有限な生成ログへの分類も、全論証空間に対する証明とは分ける。

### R2 / 高: defeat 関係を読む指示が、次の合法な攻撃と矛盾する

該当: `src/agent/prompts.py:536`（`_DEFEAT_RELATIONS_NOTE`）、`nodes.py:693` 以降。

この指示は「既に defeated な論証を攻撃するな」と要求する。一方、B→A を C が退けると、コードは A に対する別の B' を探す。保存された B→A の関係は消えないため、指示上は A を攻撃できない。相互 defeat 後に C を次の攻撃対象として push する場合も、B→C が既にあるため同じ衝突が生じる。

ここでは **論証間の defeat 関係**と、**対話木全体でその論証が退けられた状態**を同一視している。番号付きの関係ブロック自体の追加は有用だが、この禁止文は探索を不必要に止める可能性がある。原論文には O の反復が必要になる例もある（同PDF通し23頁、Example 4.4）。

**対処案:** 指定された対象に対する別の攻撃を許可し、禁止するなら「その対象に対して既に処理した同一の攻撃」に限定する。相互 defeat の局所状態を、既に解決済みという意味で扱わない。既存ログのどの終了がこの文言に起因したかは、本調査では特定していない。

### R3 / 高: schema/no_schema は表示だけの比較ではない

該当: `src/agent/argumentation_model.py:62`（`target_statement_exists`）、`:126` 以降、`arguments.py:476`（`ask_existing_undercut`）、`prompts.py:43` 以降。

| 条件差 | schema | no_schema |
|---|---|---|
| 宣言した攻撃対象の実在検査 | Conc/Ass にある文との一致を要求 | body が空なので常に通る |
| 既存論証の undercut による rebut 阻止 | 攻撃側 Ass があれば LLM 判定 | 常に None、阻止しない |
| undercut 対象 | 明示された weak_negation に限定 | 自由文の前提への攻撃を許す |
| 追加指示 | rules の連鎖、仮定、最初の前提からの対象への関与等 | 同一の詳細制約はない |
| 履歴の情報 | 本文に加え id・phase・攻撃対象等の封筒 | 発言本文のみ |
| 判定コスト | undercut 確認が追加されうる | その確認をしない |

213516 の実測では、schema の counter 493件のうち **対象等による却下29件、既存 undercut による却下44件、計73件（14.8%）**。no_schema の counter 558件では、対応する却下イベントは0件だった。これは schema の overruled 増加の具体的な経路である。ただし他の変更も同時に入っているため、SVI低下の原因とまでは断定できない。

同ログの攻撃手は schema が rebut 1079 / undercut 73、no_schema が rebut 500 / undercut 712。schema の Ass 保有発言は **316/1422（22.2%）**。手法差は、出力表現だけでなく「どの対象を攻撃可能とするか」にもある。

**対処案:** 現在の比較は「構造化＋検証＋攻撃制約を含む方式」の比較として報告する。schema 単独の寄与を知りたい場合、表示、対象検証、既存 undercut 判定を分けたアブレーションが必要。

### R4 / 高: `evaluate_attack` は意味的な否定関係を独立に検証しない

該当: `src/agent/argumentation_model.py:51`, `:101` 以降。

機械的に検査するのは攻撃メタデータと対象文の存在であり、「attacker の結論が target の結論・仮定を本当に否定しているか」ではない。**C の結論も A の結論も p なのに、C が rebut/p を宣言すれば `defeats=True` になる**ことをAPIなしで再現した。実データのすべてが誤判定という意味ではなく、LLMの自己申告を形式的な defeat の保証と呼べないという指摘である。

さらに逆向きの `ask_attack_extends` は作者の stance と履歴を見た別の LLM 判定で、順方向の自己申告と対称に検査されない。優先順位がないからといって、自然文の rebut 宣言をそのまま対称関係として扱える状態にはなっていない。

**対処案:** 「攻撃種別」「否定が成立するか」「優先順位」「defeat」「探索結果」を別々に記録する。中立な二論証判定や、人手の攻撃関係アノテーションで誤りを測る。優先順位の導入だけではこの問題は解消しない。

### R6 / 中: 番号不一致時のフォールバックが不完全

通常経路では同じ `_append_turn` とレコード追加で履歴が増えるので、数と順序は整合する。現在の main 以降に限定した関係ブロックの抽出も、既存テストで確認できる。

## 4. 評価設計の見直し

### 4.1 SVI の「±0.6」は誤差区間ではない

調査書が参照した `183206/turns20` の `svi_mini` と `svi_mini_t5` を同じファイル名で結合すると、10件の **平均絶対差は0.600、最大絶対差2.000** を再現できた。しかし符号付き平均差は **+0.550**、差の標準偏差は **0.780**。この値から「1回の判定は±0.6の範囲に収まる」とは言えない。評価設定が同一だったこともファイルのメタデータからは確認できない。

同一ログを複数回判定し、ログ内の変動と生成ログ間の変動を分けるのがよい。反復を独立な対話の件数に足してはならない。独立・同分布の誤差という仮定の下では反復平均でランダム誤差は減るが、偏りは消えない。

25セルの対応づけは、トピックとターン上限の違いをある程度抑える比較として妥当。ただし5トピックの反復測定なので、25個の独立した「新しいトピック」とは扱えない。固定したこの5トピックについての記述的比較と、未知のトピックへの推測を分け、トピック単位の感度分析と各トピックの効果を併記する。今回の区間は多重比較補正前で、確証的な検定として後付けで使わない。

### 4.2 C_0.5 は両者の合意そのものではない

この実装では代数的に `C_0.5 = mean_i min(A_i, B_i)` となる。つまり各項目の低い側の満足度を平均する独自指標であり、同じ案への明示的賛成、相互承認、反復抑制とは別である。

SVI 原尺度は交渉参加者の主観的価値を測るもので、Instrumental は Q1–Q4、Q3 は逆転する。役割を与えたLLMへの適用と二者の最小値への集約は本研究の操作化である。[著者による SVI scoring key](https://web.mit.edu/curhan/www/docs/SVI_teaching_note.pdf)

最新 free_debate の NA では、評価者自身が「個人的な条件交渉ではないため該当しない」と説明していた。測定対象との適合性を示す重要な事例として残すべきで、黙って0点・中間点に置き換えない。完全ケース除外を主解析にするか、有効項目平均を使うかは先に決めて欠測数を示す。

### 4.3 反復評価・対比較・Novelty は異なる観測単位を持つ

対比較の300判定は **75組の回答 × 2立場 × 2順序**。300個の独立標本ではない。順序別を同じ回答対内でまとめ、立場別も保持し、回答対・トピックで依存を扱う。順序を入れ替える設計は有用だが、今回43.3%の不一致があるので、それだけで信頼性が確立したとは言えない。LLM judge の位置・長さ等の偏りは先行研究でも報告されている。[Zheng et al. (2023)](https://arxiv.org/abs/2306.05685)

`eval_turn_novelty.py` が現在測るのは **同じ陣営の過去発言に対する、発言全体の新規理由の有無**である。これをそのまま「同型の反論の繰り返し」と呼ぶには、次の不足がある。

| 現状 | RQに対する問題 | 提案 |
|---|---|---|
| main/defeat/counter を一括評価 | schema の main 比率の高さと手の構成が混ざる | 全発言を副解析、defeat/counter を主解析に分ける |
| 自分の過去発言だけを提示 | 何への応答で、相手の新しい異論に答えたか判定できない | 明示的な対象発言と、その前後の必要最小限の文脈を追加 |
| 1発言に新理由が1つあれば new_reason | 長い発言が有利で、ほぼ反復でも新規と数える | 理由単位に分割し、既出/新規/補足・例示を区別 |
| 例・詳述は一律 restatement | 新しい証拠と単なる言い換えが衝突する | 独立な証拠追加と修辞的例示の境界を定義 |
| 同じ側だけの既出判定 | 相手が既に出した論点を新規と数えうる | 陣営内の新規性と対話全体の新規性を分離 |
| `closest_earlier_turn` は任意整数 | 未来番号・別陣営・不存在番号を排除しない | verdictとの条件整合、範囲、話者を検証 |
| ログごとの率を平均 | 早期終了や語数・予算の違いに依存する | 実使用ターン数、最初の共通区間、語数あたり新規理由も報告 |

文章化で JSON の封筒や手法名を消す処理は有用。ただし schema には定型の `So/Therefore` や仮定の末尾追記が残るため、手法が完全に盲検化されたわけではない。機械的な「同じ見た目」は、意味と読みやすさの同等性を保証しない。

本番前に、複数トピック・両手法・複数の手番種類から人手で全文を読む小標本を固定し、判定基準と一致率を確認する。主指標を決めた後に本番を評価する。現在の2実験フォルダには turn_novelty の保存結果はなく、本調査でも新しいLLM判定は行っていない。

## 5. 評価の実装とデータ来歴

### 5.1 例外で未保存結果を失う問題は実在する

`eval_svi_final.py:163` の `future.result()` に例外処理がなく、保存は全件完了後の174行目。1件の失敗で **その起動で既に成功した未保存の結果**も残らない。同じ構造が `eval_pairwise.py:210` と `eval_turn_novelty.py:250` にある。Novelty は全ターン上限の結果を最後に分けて保存するため、1件で複数のターン条件を巻き込む。

行ごとのチェックポイント、成功/失敗の独立保存、同じ入力ハッシュと設定に対する再開、完了後の集約が必要。過去の10/15ターン失敗の例外そのものを再現したわけではないが、喪失経路はコードで確認した。

### 5.2 Atomic Coverage はAPI失敗と未被覆を区別できない保存形式

`evaluation_coverage_atomic.py:54` では項目の失敗を None にして続行するが、63行目では `covered / len(items)`、つまり失敗項目を分母に残す。runner の出力は covered/total/ratio だけで、項目別 `addressed`、失敗数・理由を保存しない。

このため、保存された低い ratio が意味的な欠落なのか、判定APIの一部失敗なのかを後から区別できない。今回実際に失敗があったと断定する証拠はない。修正時は valid_count/error_count と項目別判定を保存し、失敗を補完・除外する基準を事前に決める。

### 5.3 fin/現行の評価モデルは保存結果から復元できない

`fin/MANIFEST.md` も Atomic Coverage のモデルを未確認としている。runner は model を引数で受け取るがJSONに残さないため、現在の `.env` を読んでも過去の実行モデルは確定しない。nano/mini の比較だったと断言することも、同一評価器だったと断言することも避ける。

最低限、model、実行日時、プロンプト/ソースのハッシュ、入力回答のハッシュ、reasoning 等の設定、統合ルール提示の有無、依存バージョン、失敗数を保存する。再最終化時の metrics は300件とも旧ログからコピーされており、**新しい最終化のモデル・トークン・費用・時間の証拠としては使えない**。

### 5.4 fin の生ログとの不一致

次のファイル名は SVI/Atomic Coverage の評価にあるが、同じ turns の `fin/raw_dialogue` にはない。

| turns | 評価に記録されたファイル |

| 15 | `02_schema_20261004_040824_468707.json` |

原本は `experiment_20261004_165642/turns<N>/raw_dialogue/` に残っている。トピック・run番号だけで現在の別ログに評価を付け替えると、別回答の点数を誤って結合する。マニフェストをファイル単位にし、入力回答ハッシュで結合することを提案する。旧保存値が直ちに無効という意味ではなく、「どの回答を採点した値か」を維持する必要がある。

原稿 `paper_draft_ja_2026-10-07.md` の結論「最終化をそろえると議論形式の間に差はなかった」は、最新SVIの schema/no_schema 比較と整合しない。旧条件の結果として限定し、新条件の結果と別に記載する必要がある。外部の `AAMAS/ja/paper_ja.tex` は今回編集・精査していない。

RQは、結果に合わせて「論点の幅なら有意になるはず」と置き換えない。元の反復抑制仮説を維持し、未支持・未検証を明記したうえで、次を **探索的な副RQ** として追加するのが適切である。

1. 論証構造と検証規則は、攻撃種別・無効な攻撃・main の更新回数をどう変えるか。
2. 同じターン数/語数の中で、独立した理由の種類数と、相手の異論に答える深さはどう変わるか。
3. 議論方式と最終化方式を交差させたとき、立場の保持と役割別満足度はどう変わるか。

幅の評価なら、理由を意味単位でクラスタ化した「ユニークな理由数」が必要で、new_reason とされた発言数や main 数をそのまま幅にしない。深さは対象の論点を実際に解消したか等として別に評価する。抽出・クラスタ定義は手法名を伏せて決め、確認用トピックを別に残す。

優先順位導入の候補文献も確認した。[Wachsmuth et al. (2017)](https://aclanthology.org/E17-1017/) は論理・修辞・弁証法を含む論証品質の分類、[Habernal & Gurevych (2016)](https://aclanthology.org/P16-1150/) は説得力の対比較を扱う。どちらも、そのまま本システムの defeat 優先順位や新規性の正解ラベルになるわけではない。品質のどの軸を優先順位に使い、順序の一貫性をどう保証するかは別の設計課題である。Kido & Kurihara の形式的な変換との同値性は本調査では証明していない。
